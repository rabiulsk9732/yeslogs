# v1.10.0-isps

The ISP index now starts with five statistics cards: total ISPs, active ISPs,
disabled ISPs, registered exporters and ISP login accounts. The directory has
search, status filtering, pagination, refresh and view/edit/delete actions.
Create and edit use theme-aligned modals with jQuery AJAX and field validation.

New ISPs require name, unique username and email, phone, password/confirmation
and explicit status. Tenant and primary login are persisted atomically. Username
and email both work at sign-in. Edit preserves an existing password when both
password fields are blank; entering a new one requires matching confirmation.
Existing tenants retain their data and login credentials and can fill missing
profile fields when edited. Version checks reject stale edits.

Disabled tenants lose public user access immediately; exporter collection is
managed separately on Devices. Delete requires a disabled ISP, exact-name
confirmation and no devices or capture policies. The profile and ISP logins are
removed together; stored flow logs, archives and audit history remain intact.

A separately deployed Director management gateway shares the existing session
key and MariaDB database, serves ISP/authentication routes and forwards runtime
APIs to the existing collector. The collector is neither rebuilt nor restarted. Remote TCP access to the old
backend port is blocked to prevent bypassing the gateway; UDP ports stay open.
The UI fetcher verifies both installed backend revisions before activation.
See deploy/ISP-MANAGEMENT.md for rollout, component ownership and rollback.

Validation: Director/store Go tests with the race detector; isolated MariaDB
migration and transaction tests; browser CRUD/validation/responsive checks;
real browser + Go + isolated MariaDB onboarding, username/email login, password
change, disabled-session rejection and confirmed deletion; dashboard regression
and release validation checks. Existing production tenants are not modified by
verification.
